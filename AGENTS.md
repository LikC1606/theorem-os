# Standalone mathematics runtime

Keep the CLI and mathematics proof behavior independent of the original DeepScientist checkout. The optional `apps/web` workbench is a separate BYOK HTTP service and Docker supervisor; it must not become a dependency of the CLI or mathematics services. There is no Electron or desktop build.

`src/math` owns mathematics services. `src/solver/modules` separates M1–M5 research decisions; `src/solver/run.ts` prepares and evaluates runs, and `src/solver/research.ts` executes cooperative role sessions with shared budgets and run-local checkpoints. `src/solver/archive.ts` owns S1 records; `src/solver/evaluation.ts` owns fixed S3 final acceptance. `src/runtime/codexSession.ts` connects to Codex through stdio. Do not reintroduce the original Core, Team services, HTTP services, role queues, or MCP orchestration into the runtime. M3 selects ready tasks, M5 assigns Lead, Researcher, Engineer and fixed-version Reviewer responsibilities; `cooperation.ts` runs the asynchronous task and integration loop, and `cooperativeProof.ts` checks and merges partial declarations; S2 learning remains a future extension.

Preserve frozen problem/source identities, isolated solver worktrees, Lean receipts, independent evaluation, and resumable runs. A model's completed message is never proof acceptance.

New runs use `deepseek-flash` with `max` reasoning through the local sub2api gateway (`http://127.0.0.1:8080/v1`) and the profile at `~/.config/deepscientist/math-sol-codex`. This local profile uses an auth command to read the existing Sub2API Westlake pool key; generated per-attempt Sub2API profiles require `SUB2API_WESTLAKE_API_KEY`. The previous direct Westlake profile is preserved as `~/.config/deepscientist/math-sol-codex-westlake`, and the `my_codex` / `gpt-6.1-sol` profile as `~/.config/deepscientist/math-sol-codex-my_codex`, for resuming older runs via `CODEX_HOME`. Do not copy credentials, alter global Codex configuration, or call real models merely to validate a local extraction.

Make the smallest requested change. Run focused tests and the headless bundle build when modifying runtime boundaries. Do not commit, publish, or modify the original checkout without an explicit request.
