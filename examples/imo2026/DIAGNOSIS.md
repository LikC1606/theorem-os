# 首次 Q1 对照实验失败排查

实验：`public-q1-comparison-20261014-055645`，2026-10-14。
证据位于仓库同级 `.deepscientist-math-runs/` 下对应实验目录。
三组均未完成原始五个目标，不能用这次结果判断单智能体和多智能体的优劣。

## 1. 模型侧 Lean 检查器在启动时失败

单智能体和独立多智能体的 `RESEARCH.md` 反复记录：

```text
ENOENT: no such file or directory, open '/proc/<host-pid>/stat'
```

宿主预检查通过，但 Codex 命令沙箱使用独立 PID 命名空间，无法访问封存依赖
描述符中的宿主 PID。启动器没有注入 `DEEPSCIENTIST_MATH_PROOF_ENVIRONMENT_SANDBOX`，
导致模型调用 `check-lean` 时在执行 Lean 前失败。宿主最终检查随后拒绝残留的
`sorry`；这是未完成的结果，不是 Lean 已检查并否定了候选证明。

修复：打开 Codex 会话前验证宿主描述符，将仍挂载的只读依赖路径和租约 socket
映射给模型侧检查器。保留原始描述符、设备号、inode、内容身份和项目配置校验；
宿主最终评测继续独立运行。

本地真实 Codex 沙箱测试复现了修复前的错误，修复后同一封存环境成功编译
`example : True := by trivial`。这验证了检查器启动及编译通路，不代表 Q1 或完整
Mathlib 导入已通过。

## 2. 协作计划把占位类型当成了证明任务

Lead 给一致性调查任务同时填入 `theoremName: counterexample_check` 和
`type: FULL_CLOSED_LEAN_TYPE`。解析器将这个带类型的 `research` 任务归一化为
`lemma`，仅检查类型字符串非空，因而接受了提示示例中的占位值。

五个原始目标全部依赖该任务。研究员交付时没有新增该定理，提交版本仍与分配
时相同，源码投影因此报 `math_task_requires_unambiguous_theorem`。这里实际是
定理缺失，不能据此推断有多个重名定理或已经发现题目反例。

修复：派发前拒绝已知占位类型并给出修正提示；计划示例使用真实 Lean 类型，
明确要求替换示例内容，没有确切命题的一致性调查使用无类型的 `research/sketch`。

## 3. Lead 规划占用了大部分求解时间

30 分钟求解预算中，首版计划约在第 24 分钟才被宿主接收。Lead 共执行 9 轮，
研究员仅执行 1 轮，另一位研究员和工程师均未启动。任务图又只有一个无依赖
的助手任务，协作并行度实际没有发挥出来。

修复：Lead 提示要求先提交任务图并返回，将证明调查和编译验证交给研究员。
启用有限单轮时间时，Lead 规划最多运行 60 秒；用户显式设置单轮时间为 0
仍表示不限时。首次检查点后若没有有效任务图，宿主生成覆盖全部原始目标的
无依赖证明任务，并为研究员分配无类型的路线调查任务。已有有效任务图保留。
回退原因写入运行状态和 `initial_plan_fallback` 事件；研究发现仍只作为建议，
原始目标继续逐项检查并接受独立最终评测。

## 4. 恢复后的 token 统计测试

先前较大回归集中的一项测试期望 9000/10800，实际得到 7000/8400。进一步定位
发现，测试替身每次打开会话都重置计数，即使是在恢复同一线程；真实适配器
使用 Codex 返回的线程累计用量。因此不能把该测试失败直接判为真实运行漏计。

修复测试替身，让同一线程的计数在会话恢复时延续，并仅在开启新线程时重置。
保留原有精确累计断言，现已通过。缺少提供方用量记录时，对照报告仍返回
`null` 并保留已有记录，不推算缺失 token。

## 5. 完整 Mathlib 导入受运行环境限制

检查器启动修复后，完整 Q1 检查仍曾在 900 秒内超时。采样栈位于
`Lean_finalizeImport` 的 `Runtime.markPersistent`，发生在模块导入阶段，尚未
执行原始目标的证明；该栈不能单独证明死锁。

相同 Lean 4.31.0 工具链逐文件核对后迁移到本地磁盘，`import Lean` 从共享
目录上超过 60 秒改善为约 6.1 秒。但完整 Q1 在本地工具链加封存依赖的配置
下仍超过 120 秒；本地普通 Mathlib 文件的对照也超过 60 秒。因此工具链迁移
和取消 FUSE 都不足以解决完整导入。

原运行位于 `login01`。账号级 cgroup 的 `memory.max` 为 12 GiB，采样时整个
账号用量接近上限，且存在大量页面回收。普通文件对照中的 Lean 已映射约
10.9 GB 数据，52 秒内只获得约 8 秒 CPU 时间，读取量约 12.2 GB。宿主可用
内存很多，并不表示该账号能使用；累计 OOM 计数也不能直接归因于本次检查。

后续验证使用集群 CPU 任务及 32 GiB 内存，不申请 GPU；继续保持原版工具链、
完整 `import Mathlib`、原始五个目标和封存依赖。独立验证证据记录在
`q1-checker-verification-20261014-165833`，与失败的正式对照分开。

该环境中的完整 Q1 普通文件编译耗时 2.827 秒。依赖镜像先验证 SHA-256，
解压成本地副本后重新封存；真实 Codex 沙箱中的完整 Q1 编译耗时 3.148 秒，
没有使用诊断缓存，宿主 Bubblewrap 独立编译耗时 4.378 秒，两者均返回 0。
输入 `Submission.lean` 与原始验证副本的 SHA-256 一致，仍只有五处原始 `sorry`
警告。这验证了编译通路，不表示五个证明已完成或最终评测已接受。

已保留该目录中的 `math-compute.env` 和 `run-on-verified-host.sh`，选择经核对
的本地工具链及依赖副本，并为后续四成员运行申请 4 个 CPU、64 GiB 内存和
0 个 GPU。脚本只有在显式传入命令时才执行；当前没有重新启动模型对照。
配置绑定 `nv-h100-018` 上的本地文件，恢复时需保持这些路径可用。

## 修复验证

- 相关运行时回归共 276 项通过，1 项显式启用的真实沙箱测试在默认回归中跳过。
- 真实 Codex 沙箱测试另行启用后通过，未调用模型。
- TypeScript 类型检查和三个无界面运行时 bundle 构建通过。
- 新增回归覆盖 2 人及 4 人配置下空计划检查点后的工作派发、有效计划保留、
  显式无限单轮时间，以及跨恢复的 token 累计。

原实验不恢复、不改写。本次排查没有调用付费模型；下一次正式对照应使用新的
构建、独立运行目录和已验证的运行配置。完整题目工作区的模型侧 Lean 检查
及宿主隔离编译已通过。
