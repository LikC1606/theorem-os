# 使用 Westlake 的 DeepSeek

模块实验可使用现有 `WESTLAKEHPC_API_KEY`，模型为 `deepseek-flash`，推理强度默认 `high`。
`prepare` 和离线协议检查不调用模型；实际运行需要启动进程已有该环境变量。
单题真实网关校准记录见 [2026-10-19 实测](../putnambench/CALIBRATION-20261019.md)。

## 准备实验

按[模块实验](EXPERIMENTS.md#准备方案)准备固定源码和构建，在准备命令中选择：

```text
--provider westlake --model deepseek-flash --effort high
```

`prepare` 不需要密钥、不访问网关、不启动兼容器。每次尝试生成独立的只读 Codex
配置和模型目录，冻结网关、模型、推理强度与配置摘要。运行与恢复都会核对身份，
不能把已有 DeepSeek 官方或 GPT 实验目录直接改为 Westlake。

冻结配置保持在 profile 根目录；Codex 的可写 `CODEX_HOME` 位于其 `runtime/` 子目录。
每次打开会话都会从冻结配置原子刷新工作副本，保留原模型目录的绝对引用；会话、日志和
线程恢复状态留在子目录中。不复制 `auth.json` 或主机凭据。Codex 自动保存的项目受信任
标记不会改写冻结输入。旧版在根目录创建的线程不自动迁移，应保留旧记录并重新准备计划。

启动实验的进程需已有 `WESTLAKEHPC_API_KEY` 环境变量。程序不从任意主机文件自动
复制凭据，也不将密钥写入题目、数学环境、配置、RPC 参数或实验档案。没有密钥时，
在启动 Codex 和兼容器前明确报错；已有实验的 `report` 不需要密钥。

## 协议兼容

Westlake 网关为 `https://hpc-api.westlake.edu.cn/v1`，公开的 DeepSeek 接口为
Chat Completions。当前 Codex 只支持 Responses，因此每个 Westlake Codex 会话
自动启动一个临时兼容器：

```text
Codex Responses -> 127.0.0.1:临时端口 -> Westlake Chat Completions
```

兼容器随会话关闭，不需要额外服务器、容器或手动启动代理。它只监听回环地址，
采用每实例随机鉴权；真实 Westlake 密钥保留在主进程中，上游请求才使用该密钥。
Codex 获得临时本地凭据，工具子进程不继承该凭据，其他 Westlake 备用密钥也会剥离。
配置中保存的是冻结的上游身份，临时端口和临时凭据不会成为恢复身份。
这些 profile 由 TheoremOS 启动，不能直接当作原生 Codex 的 Chat Completions 配置。

适配范围包括文本消息、普通函数工具、自定义 `apply_patch`、工具结果、流式输出、
DeepSeek `reasoning_content` 的后续重放以及服务商上报的用量。缺失的用量保留为缺失，
不估算 token。未知工具或多模态输入明确拒绝。Westlake 目录使用 128k 的保守客户端
上下文限制；这不是网关公布的容量，也不是实测上限。

Westlake 拒绝 `developer` 消息，兼容器按原顺序逐条映射为 `system`，保留指令内容。
流式解析接受 vLLM 的 `stop_reason` 和 `token_ids` 元数据；完成状态仍由
`finish_reason` 决定，这些元数据不会替代用量或证明证据。

同一轮工具往返中，任一上游请求缺少完整用量，整轮都会保留用量不完整标记。
已上报的部分消耗仍然可见；设置有限 token 预算时，每次上游请求前都会检查所有角色
共享的已知用量。达到门槛或缺失用量后，同一回合内的后续推理与重试也会在本地拒绝。
兼容器在向 Codex 返回完成事件前直接记账，不等待原生用量通知，也不会把两者重复累计。
未发送到上游的本地拒绝不增加请求消耗或缺失用量计数；实验比较不会把部分计数当作完整总量。

新建 Westlake 运行记录 `provider-observed-upstream-request-limit`；历史运行保留
`provider-observed-dispatch-limit`，恢复时也不追认历史消耗受过更强限制。
归档保存请求数、已完整上报数与进行中请求数；恢复遇到未结算请求会保留未知用量标记。
其他直接 Responses 服务仍使用调度级限制。

数学协作仍由 M5 和宿主调度器负责，关闭 Codex 内部多智能体和目标调度工具。
认证错误、限流和上游断流不会转换成成功完成；取消会终止正在等待的上游请求。
最终证明接受条件仍是相同的独立完整 Lean 验收。

## 验证边界

协议回归使用本地模拟 Chat Completions 服务和虚构凭据，不发送真实推理请求。
本机安装 Codex CLI 后，还可执行真实客户端的离线工具往返检查：

```bash
bun scripts/mathematics/checkWestlakeProtocol.ts
```

该检查使用临时 profile、只允许本地模拟上游，实际执行命令和 `apply_patch`，验证
推理上下文、最终回复、完整用量、两种部分缺失顺序与全部缺失的用量事件。
另有两个有限预算场景：首次请求耗尽额度或缺失用量后，工具结果触发的第二次模型请求
被本地拒绝，模拟上游始终只收到一次请求，拒绝不会生成额外的缺失用量。
检查也覆盖缺失标记在本轮结束前到达、关闭后监听端口被释放、冻结配置不变，
以及关闭后可以恢复同一线程而不触发额外推理。
离线兼容性通过不能替代真实网关的推理、限流、计费和工具行为验证。
这仍是基于回执的请求门槛，不是硬计费上限：单次请求及已经并发发出的请求仍可能超额，
发送前没有准确的输入成本。此前调度级限制下的单题校准已出现明显超额；请求级修复
目前只通过离线验证，尚未重跑真实校准。中断请求缺失用量时，完整总量与成本比较保持不可用。
