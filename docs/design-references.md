# 首页设计参考

2026-10-16 实际浏览了以下四个公开官网的首屏与后续内容。参考的是信息结构和排版方法，页面使用 TheoremOS 自己的源码、记录和图像。

| 官网 | 观察 | 在 TheoremOS 中的应用 |
| --- | --- | --- |
| [Linear](https://linear.app/) | 克制的黑色底、简洁标题，首屏下方直接出现大面积产品界面。后续用不同密度的内容形成节奏。 | 首屏展示实际研究工作台，用浅色产品区与深色验收区形成节奏，减少装饰面板与重复口号。 |
| [Cursor](https://cursor.com/) | 标题直接说明产品身份与用途，随后用真实编辑器界面和任务内容展示产品。 | 标题直接露出 TheoremOS 与数学 Agent 研究运行时；使用 Mathlib 草稿截图，保留预设候选与归档回执。 |
| [Resend](https://resend.com/) | 类别与受众表达清楚；开发体验部分直接链接代码示例。 | 让本地部署和证明档案成为明确入口；展示完整 Docker 命令与仓库的 M3 替换代码示例。 |
| [Vercel](https://vercel.com/) | 中性色、简短的产品类别名称和集中且明确的主操作。 | 以白色和中性色承载真实界面，用品牌蓝强调本地部署，绿色只用于验收状态。 |

本次没有使用这些网站的客户标志、推荐语、指标或素材。Lean、mathlib、Lean-Eval 与 Bun / TypeScript 一行表示工具生态。

## 产品事实与展示边界

- 首屏工作台截图来自真实本地 HTTP 服务的新会话，只显示未提交的 Mathlib 草稿；不调用模型或伪造成功运行。手机端使用独立视口截图，避免把桌面长图缩成不可读的文字。
- 首屏四步演示的候选源码读取自 `src/math/localExample.ts`，最终回执读取自 `docs/assets/replay.json`。反馈步骤是对预设示例的解释，不伪装成原始诊断日志。
- 最终回执始终标为“已归档的最终验收”。切换较早步骤不会把成功回执误标为当时的状态。
- GitHub Pages 官网不启动 Agent 或 Lean。演示标明预设回放、不调用模型、非实时运行；网页工作台需要自行部署 Linux / Docker 服务，并使用自己的 API Key。
- 网页历史临时保存在服务内存，源码与报告可下载；CLI 的持久恢复能力单独说明。
- 官方证明成果继续由档案数据生成，保留原项目与模型归属。
- 组件图与研究档案身份图均是结构示意，不表示固定线性流程、实时调度或已测量的性能。

## 验证重点

检查工作台截图的首屏可见和移动资源、三种开始方式与部署命令复制、四步回放与组件切换的键盘操作、移动端回执顺序、本地文件与 Pages 子路径的资源加载、320–1920 像素的换行和溢出，以及官方证明链接和档案来源的一致性。
